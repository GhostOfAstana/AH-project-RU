# Linux: измерение времени запроса

Основа: [Linux.bash](../Linux.bash), где измеряется полное время HTTP-запроса.

## Задание

Два запроса занимают одинаковое время. Один долго устанавливает соединение, другой ждёт после отправки. Почему одной общей длительности недостаточно?

## Разбор

Разные этапы дают одинаковое итоговое время. Сравните DNS, соединение, TLS, первый байт и общий результат. Это накопленные отметки времени, а не отдельные длительности, которые нужно складывать.

Пример для разрешённого endpoint; замените URL:

```bash
curl --connect-timeout 5 --max-time 15 --silent --show-error \
  --output /dev/null \
  --write-out 'http=%{http_code} dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} first_byte=%{time_starttransfer} total=%{time_total}\n' \
  'https://example.com/'
```

Сразу после команды получите код завершения через `echo $?`. Сетевая ошибка отличается от HTTP-ошибки: curl может завершиться успешно при ответе HTTP 500, если не настроен на ошибку при таком статусе.

Проведите несколько контролируемых сравнений с одной машины. Запишите время, endpoint, статус, код завершения и измерения. Один медленный запрос не доказывает проблему backend: вклад могут вносить DNS, маршрут, TLS, обработка сервером и передача ответа.

Источник: [руководство curl](https://curl.se/docs/manpage.html).
