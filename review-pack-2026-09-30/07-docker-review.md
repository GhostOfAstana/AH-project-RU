# Docker: проверка конфигурации до запуска

Основа: [Dockerfile](../Dockerfile), [Compose](../docker-compose.yml), [зависимости](../requirements.txt) и [practice.py](../practice.py).

## Задание

Что можно установить чтением файлов, не собирая образ и не изменяя конфигурацию?

## Разбор

- `api` и `db` находятся в `backend_net`; hostname базы из контейнера API — `db`. `localhost` обозначал бы сам контейнер API.
- Порт API 8000 опубликован. Одна инструкция `EXPOSE` не публикует порт на хосте.
- `postgres_data` — именованный том; Compose-файл не выбирает диск Windows.
- Краткий `depends_on` задаёт порядок запуска, но не готовность базы. Healthcheck с `service_healthy` позволяет ждать её готовности. [Документация Docker](https://docs.docker.com/compose/how-tos/startup-order/).
- В Dockerfile две инструкции `FROM`. Вторая начинает финальный этап: зависимости берутся из `requirements.txt`, приложение работает от `appuser`.
- Текущий пример не читает `DATABASE_URL` и не выполняет запросы к базе. Наличие настройки не подтверждает рабочее соединение.

Для уже запущенного учебного стенда проверьте `docker compose ps` и ограниченный вывод журнала: `docker compose logs --tail 50 api`. Перед передачей удалите секреты из копии вывода. Различайте «контейнер работает», «HTTP endpoint отвечает» и «бизнес-зависимость доступна».
